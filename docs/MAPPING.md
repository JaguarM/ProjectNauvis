The data files
==============

`data/mapping.json`
-------------------

One entry per Factorio item (214): what it is in Minecraft and which mod owns it. Hand-maintained.
The dump is a closed graph (every ingredient is made by another entry or is one of 23 raw
inputs), so only the raw inputs and the vanilla stand-ins are decisions; the rest derive
mechanically, `iron-gear-wheel` becoming `nauvis_materials:iron_gear_wheel`.

```json
"electronic-circuit": {
  "name": "Electronic circuit", "owner": "nauvis_materials",
  "item": "nauvis_materials:electronic_circuit", "craft": { "time": 0.5, "yield": 1 }, "stack": 200
}
```

| Field | Meaning |
|---|---|
| `name` | Factorio's display name, from the dump |
| `owner` | the mod that registers it |
| `item` | the Minecraft id it resolves to; for a fluid, the fluid id |
| `craft` | `time` in seconds and `yield`, from the dump. Never edit |
| `size` | Factorio's footprint `[width, depth]`, hand-entered; absent means one tile. `check_models.py` holds each `*Shape` naming a `FACTORIO_ID` to it |
| `category` | Factorio's recipe category for a recipe only a machine runs: `smelting`, `chemistry`, `oil-processing`, `crafting-with-fluid`, `rocket-building`. Absent means the hand crafts it. Facrafting keeps a categorised recipe out of the hand panel; a machine names the category it runs |
| `stack` | Factorio's stack size, on every registered item and every stand-in; `check_models.py` holds `Stacks.of(n)` or the pack's `StandInStacks` line to it |
| `stand_in` | an existing Minecraft item covers it; nothing is registered |
| `raw` | the dump gives it no recipe: ores, fluids, filled barrels |
| `skip` | never registered, with a reason |

Stand-ins: `raw_iron`, `raw_copper`, `coal`, `cobblestone` (stone), `iron_ingot` and
`copper_ingot` (plates), `oak_log` and `oak_planks` (wood), `stone_bricks`, `cobblestone_wall`,
`chest`, `redstone_lamp`, `dirt` (landfill), `gray_concrete`, `yellow_concrete` (hazard),
`iron_door` (gate, the weakest), `water`, `cod`. Skipped: blueprints, the deconstruction planner,
the axes, the underground belts, pipe-to-ground, the trains and vehicles, the pump, the circuit
network. `gen_technologies.py` reports a technology that unlocks a skipped item.

Seven items cannot be generated and `gen_recipes.py` lists them by reporting every ingredient no
generated recipe produces: `solid-fuel`, `uranium-235`, `uranium-238`, `heavy-oil`, `light-oil`,
`petroleum-gas`, and `uranium-processing` (a probabilistic output). `uranium-ore` is the one raw
input that is new content (an ore block and worldgen), unscheduled.

Naming: ids derive from the Factorio id; display names from the dump. Where two Factorio releases
disagree, the dump's spelling wins (`science-pack-1`, `logistic-chest-storage`).

`data/fluid_recipes.json`
-------------------------

The recipes the dump cannot hold, transcribed from Wube's `recipe.lua` in the dump's units with a
machine category each: the refinery's (three fluids at once), solid fuel's three routes, and the
fourteen barrel recipes. The generator reads both files as one list: a `Liquid` ingredient becomes
a `fluid_ingredient`, a liquid product a `fluid_result`, and a recipe with any fluid gets no bench
fallback. They are named after the recipe (`nauvis_fluids:solid_fuel_from_heavy_oil`) and a
technology resolves such a name to its key without an `unlocks` row. Coal liquefaction is left out
on purpose. `fluidbox_index` is not carried; the machine keeps the port table (`ARCHITECTURE.md`).

The `unlocks` table
-------------------

A technology effect names a recipe, and Factorio's recipe names are not always item names
(`small-lamp` makes `lamp`, `solar-panel-equipment` makes `portable-solar-panel`): fifteen rows
map those. Eight rows are `null`, meaning no counterpart in the pack (the oil routes the dump
carries as raw). A name in neither table is a `GenError`, never a dropped unlock.

`data/technologies.json`
------------------------

Factorio's tree, 216 technologies, generated by `gen_technologies.py` into
`nauvis_research/.../nauvis_research/technology/<name>.json` plus a vanilla advancement per
technology (criterion `minecraft:impossible`, awarded by the server when the world completes it;
icon is the first vanilla unlocked item or the lab, since an icon is registry-validated). A
technology is paid in exactly one of two ways: a cost (units, one of each pack per unit, seconds
a unit) or a trigger, `craft-item` (an item and a count, heard from bench, furnace and panel) or
`mine-entity` (a resource id, heard through `MiningListeners`). `modifiers` go through whole as
`{"type": ..., "modifier": n}` with an `ammo_category` or `turret_id` folded into `target`, and
the research mod sums the earned ones by `type` or `type@target` for `Bonuses`. The generator
fails on a tree that cannot be bootstrapped from an empty world, drops technologies whose
prerequisites are missing (transitively, and names them), and refuses an unknown trigger type.

`data/removals.json`
--------------------

Which vanilla recipes stop existing, generated by `gen_removals.py` into a built-in datapack in
the `nauvis` mod at `Pack.Position.TOP`, each file a `neoforge:never` condition. Every entry names
a `replaced_by` recipe and the build fails if that recipe is not shipped. Two kinds: a **conflict**
(a vanilla recipe making an item the mapping puts a Factorio item on; checked rather than listed,
so shipping a pack recipe for a stand-in fails the build until vanilla's is removed) and a
**bypass** (vanilla doing a job Factorio has a machine for; a judgement, only ever a list).
`mirrors` names vanilla recipes a pack recipe reproduces (planks), and `kept` names conflicts that
are iron changing shape (block and nuggets); both stand the check down. Minecraft's own recipes are
read from the client jar in the Gradle cache; the check skips itself when it is absent.

The opening: four planks is a stone pickaxe and the wooden one has no recipe (a stone recipe cannot
be the first pickaxe). `mineable/pickaxe` gains the axe, shovel and hoe tags; tiers are untouched.
